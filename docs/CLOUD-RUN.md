# Результаты облачного прохождения

21 сентября 2026 года. Два опыта выполнены через настоящий Yandex Workflows; оба восстановленных кластера автоматически удалены контроллером.

| --- | --- | --- | --- | --- | --- | --- |
| `positive-cloud-001` | PASS | 16/16 | 420.553 с | 0.594 с | 32.298 с | CONFIRMED_ABSENT |
| `negative-cloud-001` | FAIL | 15/16 | 478.079 с | 0.498 с | 32.935 с | CONFIRMED_ABSENT |

## Что доказали опыты

**Положительный:** после создания ручной копии изменена сумма заказа в исходной БД, перезаписан документ и установлен маркер удаления. Восстановленная БД содержит исходные десять заказов с суммой 55 000 копеек и прежними ссылками. Все десять точных версий файлов доступны, их SHA-256 совпадают. Workflows завершился со статусом `FINISHED`.

**Отрицательный:** после первого PASS физически удалена исходная версия документа заказа № 1. При повторном восстановлении все проверки БД, девять оставшихся документов и целевое время прошли. Единственная ошибка — `attachment:1 / MISSING_VERSION`. Workflows ожидаемо завершился как `FAILED / STEP_FAIL`; контроллер предварительно удалил временный кластер и сохранил отчет.

Общее время процессов, включая опрос, проверки и уборку: около 9 мин 14 с и 10 мин 9 с. Это измерения малого учебного набора, а не гарантия RTO/RPO рабочего приложения.

## Условия

PostgreSQL 16, `s3-c2-m8`, 2 vCPU, 8 ГБ RAM, SSD 10 ГБ на кластер, один приватный хост в `ru-central1-b`. Исходные ресурсы и восстановление находятся в отдельных каталогах и VPC. Функции Python 3.12 подключаются к БД по TLS; пароль и ключи приходят из Lockbox. State и планы Terraform хранятся вне OneDrive. Секретные значения не включены в публикуемые артефакты.

## Исправления по результатам прохождения

1. Квота сетей увеличена с двух до трех: существующий `default` плюс две выделенные сети.
2. Политики бакетов явно сохраняют доступ оператору. Функциям нужны базовые роли на конкретных бакетах; политики дополнительно ограничивают ключи и операции.
3. Для соединений функций SG разрешают TCP 6432 из служебного диапазона `198.19.0.0/16`.
4. В Workflows используется `While`: графовые циклы через `next` отклоняются API.
5. Native schedule принимает `0 3 * * * *`; варианты с `?` и пятью полями отклонены. В первоначальном прогоне использовался таймер v1. Перед публикацией он заменен на API v2; отдельно проверена доставка события приватной функции и установка `*/15 * * * ? *`, см. [результат](../artifacts/cloud/timer-v2-validation.json).
6. Расписание явно снимается через `yc serverless workflow update --remove-schedule`. Одного значения `false` недостаточно из-за Optional+Computed в провайдере; удаление Workflows с расписанием запрещено API. Снятие подтверждено облаком, ID процесса сохранен.
7. Запоздалые ответы создания Lockbox согласованы с успешными операциями через Operations API без повторного создания ресурсов.

## Уборка и стоимость

Оба временных кластера и исходный PostgreSQL удалены. Операция удаления источника завершилась без ошибок 21 сентября 2026 года в 19:01:58 UTC. Удалены функции, Workflows, таймер, бакеты со всеми версиями, ключи, секреты, сервисные аккаунты и группы логов. Обе сети удалены после освобождения служебных подключений Cloud Functions. Оба Terraform state пусты.

[Проверка очистки](../artifacts/cloud/cleanup-verification.json) подтверждает отсутствие перечисленных ресурсов в обоих каталогах. Для самих тестовых каталогов запущено удаление с `--delete-after 0s`; на последней проверке статус `PENDING_DELETION`. Это асинхронная служебная операция облака. Каталог и сеть `default` не изменялись, `default` остается ACTIVE.

Две резервные копии удаленного исходного кластера сохраняются сервисом на 7 дней **без тарификации**, после чего удаляются автоматически; ручное удаление после удаления кластера недоступно. Это [штатное поведение Managed PostgreSQL](https://yandex.cloud/ru/docs/managed-postgresql/concepts/backup#storage).

Платежная детализация хранится локально и не входит в публикуемые артефакты. Промежуточный учет не используется как окончательная стоимость опыта.

Полный аудит отказов не выполнялся: границы проверок перечислены в [VALIDATION.md](VALIDATION.md).
